## 内存、栈与业务核对

- 确认并修复的运行期存储增长是 F5。压力场景中，一个早期有效项加上另一个 ID 的 1,000 次更新，旧实现按其 push 逻辑会保留 1,001 个堆节点；新实现实测 `size()==indexSize()==2`，取消后立即降为 1，再取出最后有效项后为 0。旧值是操作次数推导，不是旧二进制测量。
- RaceMenu `SetVariant` 栈对象未发现悬空使用：本机 `E:/source/repos/RaceMenu/skee64/OverrideInterface.cpp:2525`、`:2723` 同步复制值，字符串进入其固定字符串表；没有保留 SLACS2 的栈 variant 或临时 `c_str()`。
- P+ 回调将 VM 数组同步转为自己的 FormID/整数值；回调通过共享 gate/state 管理所有者。FormDelete 在 SKSE 同步钩子中读取 FormID 后执行清理。未证实这些路径存在 UAF、越界或锁递归死锁。
- 配置 JSON 递归深度在 `src/config/Settings.cpp:91` 限制为 32；持久化 reader/record 的长度检查也已检查。本次未确认栈溢出或任意长度记录导致的越界。
